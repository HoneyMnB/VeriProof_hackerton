## 1. 재검증 결론과 제품 경계

### 1.1 현재 구조의 문제

현재 창작자 사이드바에는 새 대화, Creator assistant, 라이브러리, A2A sandbox,
공개 마켓플레이스가 나열되어 있다. 이는 다음 이유로 사용자 작업 모델과 맞지 않는다.

| 현재 항목 | 문제 | 올바른 위치 |
|---|---|---|
| 새 대화 + Creator assistant | 행동과 현재 화면을 중복해 두 개의 메뉴처럼 보이게 함 | 새 대화는 단일 행동, 작업공간은 기본 화면 |
| 대화 기록 부재 | 대화 중심 제품에서 과거 작업을 찾고 재개할 수 없음 | 사이드바의 작업 기록 모달 |
| A2A sandbox | 개발자 검증 도구를 판매자에게 노출 | staff 전용 개발자 도구 또는 숨김 경로 |
| 수입·지출·구독·지침 폼 | 상시 입력 필요가 없는 세부 운영 정보를 탐색에 혼합 | 계정 설정, 자산 상세, 전용 관리 화면 |
| 가격 설정 | 가격은 상품별 조건인데 전역 설정처럼 보일 위험 | 개별 자산 상세/등록 초안 |
| 공개 마켓플레이스 | 판매자 내부 탐색과 외부 홈을 동급 메뉴에 배치 | 하단 보조 탐색 또는 별도 공개 홈 |

### 1.2 확정 제품 경계

VeriProof는 세 개의 표면을 명확히 분리한다.

```text
창작자 작업공간              공개 마켓플레이스              개발자 검증 도구
대화·등록·내 자산             외부 탐색·구매·A2A            A2A/x402 진단
로그인 계정 범위              공개 자산만                   staff/DEBUG만
```

- **창작자 작업공간**: 저작물 등록을 준비하고, 자신의 라이브러리·판매·권리를
  관리하는 주 표면이다.
- **공개 마켓플레이스(Discover)**: Unsplash/Pexels처럼 외부 방문자와 구매자
  에이전트가 공개 자산을 탐색하는 독립 홈이다.
- **A2A Sandbox**: 해커톤 데모/개발 검증 전용이다. 일반 판매자의 기능으로
  설명하거나 노출하지 않는다.

## 2. 사용자 작업 흐름

### 2.1 창작자 기본 흐름

1. 이메일로 가입 또는 로그인한다.
2. 기본 화면인 작업공간에서 비서와 대화한다.
3. 필요하면 파일을 대화에 첨부해 질문·분석·아이디어 검토를 한다.
4. 사용자가 명시적으로 저작물 등록을 시작한다.
5. 등록 캔버스와 대화를 오가며 제목, 설명, 공개 범위, 상품별 가격·라이선스를
   완성한다.
6. 최종 요약을 읽고 등록을 확정한다.
7. 구독 이용량 확인 → 저장·분석 → 앵커·인증서 → 공개 인덱싱 결과를 확인한다.
8. 라이브러리에서 개별 자산의 가격·공개·라이선스·판매 결과를 관리한다.

### 2.2 외부 구매/에이전트 흐름

1. Discover에서 공개·앵커 완료된 자산을 탐색한다.
2. 자산의 보호된 미리보기, 태그, 가격, 라이선스 조건을 확인한다.
3. 브라우저 구매자 또는 외부 에이전트가 x402 조건을 받는다.
4. 필요하면 협상한다.
5. 결제 검증 후 라이선스, 다운로드 권한, 인증서를 받는다.

### 2.3 개발자 검증 흐름

1. staff 개발자 계정으로 로그인한다.
2. 계정 설정의 개발자 도구에서 Sandbox로 이동한다.
3. 공개 데모 자산을 이용해 402 → 협상 → 목업 결제 → 정산·인증서 흐름을 점검한다.

## 3. 정보 구조와 화면별 책임

| 표면 | 주 질문 | 허용 행동 | 제외할 행동 |
|---|---|---|---|
| 작업공간 `/` | “무엇을 등록·관리·탐색할까?” | 대화, 파일 첨부, 등록 시작, 작업 기록 재개 | 전역 가격 설정, 개발자 프로토콜 진단 |
| 라이브러리 `/library` | “내 자산의 권리와 판매 상태는?” | 자산 상세, 가격/공개/라이선스 관리, 인증서·판매 확인 | 다른 창작자 비공개 자료 조회 |
| Discover `/discover` | “어떤 공개 자료를 라이선스할 수 있나?” | 검색, 필터, x402 접근 조건 확인 | 판매자 개인 설정, 원본 파일 직접 노출 |
| 계정 모달 | “내 계정·언어·지갑·플랜은?” | 프로필, 언어, 지갑, 구독/결제수단, 로그아웃 | 상품별 가격 설정 |
| 개발자 도구 | “프로토콜이 실제 동작하는가?” | A2A/x402 진단·로그 확인 | 일반 사용자 기본 탐색 |

## 4. 사이드바 상세 명세

### 4.1 최종 메뉴 구조

```text
┌────────────────────────────┐
│ VeriProof          [접기]  │  ← 고정 헤더
│                            │
│ [✎] 새 대화                │  ← 행동, 화면 메뉴 아님
│                            │
│ [▤] 작업 기록              │  ← 모달
│ [▣] 내 라이브러리          │  ← 화면 전환
│                            │
│                            │
│ [⌕] 공개 마켓플레이스      │  ← 하단 보조 링크
│ ────────────────────────── │
│ [아바타] 계정              │  ← 최하단 고정
└────────────────────────────┘
```

### 4.2 항목의 의미와 동작

| 항목 | 유형 | 동작 | 비고 |
|---|---|---|---|
| 새 대화 | 행동 | 현재 대화 뷰를 비우고 새 세션을 생성 | 기존 이력은 삭제하지 않음 |
| 작업 기록 | 모달 | 최근 대화, 등록 초안, 자산 관련 작업을 검색·재개 | 대화 화면과 중복되지 않음 |
| 내 라이브러리 | 탐색 | 로그인 창작자의 자산 목록으로 이동 | 개별 가격/공개 관리의 소유 위치 |
| 공개 마켓플레이스 | 외부 탐색 링크 | Discover로 이동 | 별도 하단 그룹, 기본 작업 메뉴 아님 |
| 계정 | 모달/메뉴 | 프로필·언어·지갑·플랜·결제·로그아웃 | staff만 개발자 도구 추가 |

`Creator assistant` 메뉴는 제거한다. 어시스턴트는 메뉴가 아니라 기본 작업공간의
상호작용 주체이기 때문이다.

### 4.3 작업 기록 모달

참조 프로그램의 히스토리 모달 패턴을 따른다.

- 최근 대화 세션과 진행 중/완료된 등록 초안을 시간순으로 표시한다.
- 검색은 대화 텍스트, 저작물 제목, 초안 제목을 대상으로 한다.
- 항목을 누르면 해당 대화 세션과 연결된 등록 캔버스를 복원한다.
- 모달 밖 클릭, 닫기 버튼, Escape로 닫힌다.
- 최초 로딩에는 스켈레톤을 표시하고, 빈 결과에는 생성 행동을 안내한다.

### 4.4 접기/펼치기 규칙

참조 프로그램처럼 **아이콘 열은 이동하지 않고 라벨만 사라져야 한다.**

- 펼침 폭과 접힘 폭 모두 아이콘 중심 X좌표를 동일하게 유지한다.
- 접기 버튼도 절대 위치 또는 고정 아이콘 열 안에서 같은 기준 좌표를 유지한다.
- 접힌 상태에서 브랜드 텍스트와 메뉴 라벨만 숨긴다.
- 모든 아이콘은 tooltip과 `aria-label`을 제공한다.
- 모바일은 독립적인 오버레이/드로어로 처리하며, 데스크톱 폭 축소를 단순 재사용하지
  않는다.

### 4.5 일반 사용자에서 숨길 항목

- A2A Sandbox
- OpenAPI, agent manifest, webhook 로그
- 체인 RPC 상태, 모델 이름, 내부 목업 여부를 제외한 기술 진단 정보

이 정보는 관리자/개발자 도구에 둔다. 사용자는 “등록이 완료됐는가, 인증서가
발급됐는가, 판매가 발생했는가”를 봐야 한다.

## 5. 대화·첨부·등록 캔버스 UX

### 5.1 컴포저

하단 입력창은 세 가지 기능만 가진다.

- `+`: 작은 행동 메뉴 열기
- 메시지 입력
- 전송

기술 모델 헤더는 사용자 가치가 없으므로 제거한다. 모델/연결 상태는 개발자 상태
화면 또는 오류 시에만 노출한다.

### 5.2 `+` 행동 메뉴

| 표시 문구 | 의미 | 등록 캔버스 |
|---|---|---|
| 파일 첨부 | 대화에 파일을 추가해 질문·분석·비교에 사용 | 열지 않음 |
| 저작물 등록 시작 | 등록 의도를 명시하고 초안 작업을 시작 | 열기 |

`작업 등록`은 모호하므로 사용하지 않는다. `저작물 등록 시작`은 등록 의도를 명확히
표현하므로 유지하는 편이 낫다.

메뉴 dismiss 규칙은 필수다.

1. 메뉴 밖 pointer down
2. Escape
3. 메뉴 항목 선택
4. 새 대화/라우트 전환
5. 입력창 포커스 이동 후 일정 시간 안에 메뉴 외부로 이동한 경우

### 5.3 첨부와 등록 의도 분리

```text
파일 첨부
 ├─ 대화 첨부 카드 생성
 ├─ 에이전트에게 분석/질문/비교 요청 가능
 └─ 사용자가 “등록”을 선택하거나 명시적으로 요청할 때만
        → 등록 초안 캔버스 열기
```

파일을 올린 것만으로는 자산, 공개 자산, 검색 인덱스, 앵커, 인증서를 만들지 않는다.
첨부 원본의 보관·삭제·등록 전환은 사용자가 명시적으로 제어한다.

### 5.4 등록 캔버스

- 우측 패널은 등록 의도 확인 후에만 열린다.
- 사용자는 대화와 캔버스를 동시에 본다.
- 에이전트는 질문·권리/가격 조언·누락 경고를 제공한다.
- 사용자는 모든 필드를 직접 수정할 수 있다.
- 필드 값에는 `사용자 입력`, `에이전트 제안`, `이미지 분석` 출처를 표시한다.
- 직접 수정값은 어떤 자동 제안보다 우선한다.
- 닫아도 초안은 유지하며, 작업 기록에서 다시 연다.

### 5.5 최종 확인과 서버 강제

최종 등록 전 요약에는 파일명·해시, 자산 유형, 제목/설명, 공개 범위, 가격,
라이선스, 구독 이용량, 앵커/인증서 실행 범위를 표시한다.

등록 버튼은 다음 조건을 모두 만족할 때만 활성화한다.

1. 필수 필드가 유효함
2. 사용자가 최종 확인함
3. 서버가 발급한 확인 토큰이 유효함
4. 실제 업로드 파일 해시가 초안 해시와 일치함
5. 구독의 잔여 등록 권한이 있음

클라이언트 표시만으로 성공을 표현하지 않는다. 서버의 저장·앵커·인증서 결과를
재조회해 완료 상태를 제시한다.

## 6. 자산별 가격·공개·라이선스 정책

### 6.1 가격은 전역 설정이 아니다

가격은 `IpAsset`별 판매 조건이다. 따라서 계정 모달이나 사이드바에 전역 가격 설정을
두지 않는다.

| 설정 | 소유 위치 | 예시 |
|---|---|---|
| 최소 가격, 목표 가격 | 등록 캔버스·자산 상세 | 이미지 A 5 USDC, 상품 B 30 USDC |
| 공개/비공개 | 등록 캔버스·자산 상세 | 공개 카탈로그 노출 여부 |
| 라이선스 사용 범위 | 등록 캔버스·자산 상세 | 개인/상업/재배포 제한 |
| 구독 플랜·결제 수단 | 계정 설정 | 월간 등록 권한 구매 |

### 6.2 라이브러리 상세 패널

내 라이브러리의 자산 카드/상세 화면은 다음을 관리한다.

- 권리 증명·앵커·인증서 상태
- 보호된 미리보기
- 공개 범위
- 자산별 가격과 라이선스 조건
- 판매 건수, 정산 내역, 구매자에게 제공된 라이선스
- 유사 공개 자산 탐색과 다음 조치

공개 전환이나 가격 변경은 사용자 확인과 서버 소유권 검증을 거친다.

## 7. 계정·이메일 로그인·개발자 로그인

### 7.1 현재 구현과 차이

현재 구현은 Django `username` 기반 가입/로그인이다. 이메일 주소를 계정 식별자로
강제하지 않으며, 개발자 계정과 빠른 로그인 버튼도 없다. 이는 아래 목표 상태로
교체해야 한다.

### 7.2 이메일 계정 정책

- 로그인 ID는 정규화된 이메일 주소다.
- 가입 폼은 이메일, 비밀번호, 비밀번호 확인을 받는다.
- 이메일은 DB 수준에서 유일해야 한다.
- 기존 Django 기본 User를 유지한다면 `username`에 정규화된 이메일을 복사하고,
  `email`도 동일하게 저장한다. 또는 전용 사용자 모델 전환 여부를 별도 결정한다.
- 계정 설정의 표시 이름은 로그인 ID와 독립적이다.
- 세션 로그인 이후 사용자별 지갑·라이브러리·대화·초안에 대한 권한 검사를 강화한다.

### 7.3 로컬 개발자 계정

로컬 시연을 위해 idempotent seed/management command로 계정을 생성한다.

| 값 | 정책 |
|---|---|
| 이메일 | `admin@test.com` |
| 권한 | `is_staff=true`, 개발자 도구 접근 가능 |
| 생성 환경 | `DEBUG=true` 또는 명시적 로컬 seed 명령에 한정 |
| 비밀번호 | `a123456789?` (`?`를 실제 문자로 포함) |

개발자 로그인 버튼은 로그인 화면에만 표시하며 `DEBUG=true`에서만 동작한다. 버튼은
프런트엔드에 자격증명을 노출하거나 임의 세션을 만들지 않고, CSRF 보호된 서버
엔드포인트가 시드 계정을 인증한 뒤 세션을 만든다. 운영 환경에서는 URL과 버튼을
모두 비활성화한다.

### 7.4 계정 모달 구성

일반 사용자:

- 표시 이름
- 언어
- 창작자 지갑 연결
- 구독 및 결제 수단
- 로그아웃

staff 개발자 추가 항목:

- 개발자 도구 → A2A Sandbox
- 로컬 목업/실체인 어댑터 상태
- 데모 카탈로그 시드 상태

## 8. 에이전트 컨텍스트·공개 자료 탐색

### 8.1 읽기 권한

에이전트는 다음을 근거로 대화한다.

- 로그인 창작자 본인의 라이브러리·등록 초안·대화 이력·행동 지침
- 본인의 구독·판매·수입·지출·인증서
- 공개·앵커 완료된 다른 창작자의 카탈로그 메타데이터·보호된 미리보기

에이전트는 다른 사용자의 비공개 자산, 원본 파일, 지갑 비밀키, 개인 결제 정보에
접근하거나 추론해서는 안 된다.

### 8.2 유사 이미지/자료 탐색

검색 비용과 품질을 함께 관리하는 순서는 다음과 같다.

1. 등록 시 콘텐츠 SHA-256, 지각 해시, 사용자 태그, Gemini 분석 태그, 자산 유형,
   가격·라이선스·공개 상태를 저장한다.
2. 질의를 텍스트·태그·유형·가격·라이선스 조건으로 구조화한다.
3. 권한 범위 안에서 텍스트/태그와 해시 거리로 후보를 먼저 제한한다.
4. 후보 썸네일만 컨택트 시트 한 장으로 합친다.
5. Gemini Vision은 최대 1~2회로 후보를 재정렬한다.
6. 에이전트는 결과를 유사 후보로 설명하며 침해·표절을 단정하지 않는다.

컨택트 시트에는 원본이 아니라 보호된 썸네일만 넣는다. 후보가 충분히 좁혀지거나
텍스트/해시 점수가 명확하면 Vision 호출을 생략한다.

## 9. Discover 데모 카탈로그와 구매 시연

### 9.1 목적

Discover의 예시 이미지는 화면 장식용 mock이 아니다. 해커톤 시연에서 외부 에이전트가
실제 공개 자산을 탐색하고 x402 결제 조건·협상·정산·인증서를 확인할 수 있는
**실제 로컬 데모 판매 상품**이어야 한다.

### 9.2 데모 자산 구성

관리자 창작자 계정에 연결된 서로 다른 이미지 15개를 준비한다.

| 분류 | 수량 | 예시 |
|---|---:|---|
| 작품 사진 | 3 | 설치 작품, 도자기, 조형 작품 촬영 |
| 팝아트 | 3 | 강한 색상·그래픽 일러스트 |
| 풍경사진 | 3 | 도시/자연/해안 풍경 |
| 유화 인물화 | 3 | 서로 다른 구도·색감의 인물 회화 |
| 소품 제품 사진 | 3 | 직접 제작한 작은 제품·오브제 촬영 |

각 항목은 서로 다른 시각적 구도와 파일을 가진다. 동일 이미지의 색상만 바꾼
복제 데이터는 사용하지 않는다.

### 9.3 생성·등록 방식

별도 로컬 전용 `seed_demo_catalog` 관리 명령을 만든다.

1. 개발자 계정과 Creator를 idempotent하게 준비한다.
2. 생성된 이미지 파일을 명시적 seed asset으로 보관한다.
3. 각 파일을 일반 등록 서비스에 전달한다.
4. 실제 SHA-256, 보호된 미리보기, Gemini 분석 태그·카테고리, 가격, 공개 조건을
   저장한다.
5. 데모용 목업 구독 권한을 부여한다.
6. 목업 Solana 앵커와 인증서 경로를 통과시킨다.
7. `public + anchored` 상태일 때만 Discover에 노출한다.

직접 ORM으로 `IpAsset`을 삽입하거나 UI용 거짓 데이터로 채우지 않는다. seed 명령은
실제 등록 서비스·저장소·목업 체인 어댑터를 호출해야 한다.

### 9.4 가격·태그·해시

- 가격은 자산 성격별로 다르게 설정하고, 최소/목표 가격을 모두 저장한다.
- 태그는 Gemini 분석 결과와 seed 제작자가 확인한 설명을 구분해 저장한다.
- SHA-256은 실제 파일 바이트로 계산한다.
- 지각 해시는 유사 검색 인덱스 구현 단계에서 실제 이미지 바이트로 계산한다.
- 공개 API에는 원본 위치·원본 바이트를 넣지 않는다.

### 9.5 외부 에이전트 구매 시연

```text
Discover/공개 catalog
  → 외부 에이전트가 공개 자산 조회
  → HTTP 402 결제 조건 수신
  → 협상 API (선택)
  → 목업 USDC 결제 증빙
  → settlement 검증
  → License + 인증서 + 만료형 다운로드 경로
```

seed 완료 검증에는 각 분류에서 적어도 한 자산에 대해 이 전체 흐름을 실행한다.

## 12. 리스크와 결정 필요 사항

1. **개발자 비밀번호 사용 범위**: 확정된 로컬 개발자 비밀번호 `a123456789?`는
   `DEBUG=true` 시드/빠른 로그인에만 사용한다. 운영 계정·배포 환경에는 절대 사용하지
   않으며, 운영 전에는 해당 계정을 비활성화하거나 안전한 자격증명으로 교체한다.
2. **이메일 사용자 모델 전환**: 이미 생성된 로컬 사용자 데이터가 있으면 전용 custom
   user model 전환은 위험하다. 해커톤 범위에서는 기본 User의 `username=email` 전략이
   더 안전하다.
3. **이미지 생성 저작권**: 데모 생성 이미지는 명확한 로컬 시연 asset으로 표시하고,
   실제 상업 판매 자산으로 오인되지 않게 seed metadata에 출처를 기록한다.
4. **Vision 비용**: 컨택트 시트 재검토는 반드시 후보 상한·호출 상한을 서버 설정으로
   강제해야 한다.
5. **권한**: 현재 지갑 query 기반 경로는 해커톤 최소 구현이다. 이메일 세션과 Creator
   지갑의 강한 소유 연결을 등록/라이브러리/대화 API 전체에 적용해야 운영 수준이 된다.
