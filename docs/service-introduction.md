# VeriProof AI — 서비스 소개서 (내부 공유용)

> **Agentic IP Protocol & Automated Licensing Marketplace**
> AI 에이전트가 사람의 개입 없이 창작물 저작권을 협상하고 결제·정산하는 에이전트 전용 라이선싱 프로토콜/마켓플레이스.

- 문서 성격: **서비스 소개서 + 비즈니스 IR 성격(내부 정렬용)**
- 목적: 서비스의 **정의·개념·가치**와 **개발 방향**을 팀 내부가 동일하게 이해하기 위함
- 형식: 슬라이드 덱 기준. 각 페이지에 들어갈 내용을 페이지별로 정리
- 작성일: 2026-07-23 · 버전: v1.0
- 관련 문서: [PRD](./PRD.md) · [아키텍처·데이터모델](./00-architecture-and-data-model.md) · [발표 슬라이드 덱](./presentation.md) · [SPEC 목록](./specs/)

## Slide 3 — 서비스 정의 (What It Is)

**[페이지 목적]** 서비스를 한 문장 → 세 층위로 정확히 정의.

**[핵심 메시지]** "VeriProof AI는 사람이 아니라 **AI 에이전트가 결제 주체**가 되는 저작권 거래 인프라다."

**[담을 내용]**
- **한 문장 정의**: "창작자 IP를 대화형으로 등록하고, 외부 AI 에이전트와 HTTP 402(x402) 기반으로 협상하여, Solana(USDC)로 즉시 정산하는 에이전트 전용 저작권 라이선싱 프로토콜 및 마켓플레이스."
- **세 층위 정의**
  1. **프로토콜** — AI가 IP에 접근할 때 "협상·결제 방법"을 런타임에 규격으로 전달 (x402 + a2a-x402 + AP2)
  2. **마켓플레이스** — 창작자가 IP를 등록하고, 에이전트가 발견·협상·구매하는 장
  3. **결제 레일** — 초소액 USDC 온체인 정산 + 위변조 불가 인증서 발급
- **한 줄로 아닌 것(Not)**: 사람용 스톡 판매몰이 아니다 · NFT 아트 마켓이 아니다 · 단순 이미지 DRM이 아니다 → **"에이전트가 자율 결제하는 M2M 라이선싱"** 이 본질

**[시각 구성 제안]** 상단 큰 한 문장, 하단 3열 카드(프로토콜/마켓플레이스/결제레일). "Not" 항목은 흐린 취소선 카드로 대비.

## Slide 4 — 우리가 푸는 문제 (The Problem)

**[페이지 목적]** 서비스 존재 이유를 문제 관점에서 못박음.

**[핵심 메시지]** "AI는 매일 수십억 장을 학습하지만, 창작자는 보상받을 길도, AI는 스스로 결제할 길도 없었다."

**[담을 내용]**
- **P1 · 무단 학습/크롤링** — 창작자 IP가 동의·보상 없이 AI 학습·생성에 소비됨
- **P2 · 결제 장벽** — 카드 결제는 회원가입·본인인증·CVC 필요 → **AI 에이전트가 스스로 결제 불가**
- **P3 · 초소액 불가** — 건당 고정 수수료 구조(예: ~300원) → **1~100원짜리 마이크로 라이선스가 성립하지 않음**
- 결론 문구: "그래서 **M2M(기계 대 기계) 거래 시장은 인프라가 없어 존재하지 못했다.**"

**[시각 구성 제안]** 문제 카드 3장 순차 등장. 하단에 "→ 시장 부재(공백)" 화살표로 다음 장(왜 지금) 유도.

## Slide 5 — 왜 지금인가 (Why Now)

**[페이지 목적]** 타이밍의 정당성 — 지금 만들 수 있게 된 이유.

**[핵심 메시지]** "세 기술이 동시에 성숙한 지금, 에이전트 커머스가 처음으로 가능해졌다."

**[담을 내용]**
- 지금까지 없던 것: AI가 스스로 라이선스를 사는 **표준 협상·정산 프로토콜**
- 이제 가능해진 것(3대 기술 교차점)
  - **x402 (HTTP 402 부활)** — 웹 네이티브로 "결제하라"를 런타임에 요구
  - **Solana** — 초저수수료·초고속 → 초소액 결제를 실제로 성립시킴
  - **Gemini 3.6** — 멀티모달 분석 + 자율 협상 추론
- 결론: **x402 ∩ Solana ∩ Gemini = 에이전트 커머스의 탄생**

**[시각 구성 제안]** 3원 벤 다이어그램, 교집합에 "Agent Commerce" 라벨.

## Slide 6 — 핵심 개념·용어집 (Shared Vocabulary)

**[페이지 목적]** 내부가 같은 단어를 같은 뜻으로 쓰게 만드는 **정렬의 핵심 페이지**.

**[핵심 메시지]** "이 용어들이 이 문서와 코드·스펙 전반의 공용어다."

**[담을 내용]** (표)

| 용어 | 정의 |
|------|------|
| **에이전트 커머스** | 사람이 아닌 AI 에이전트가 거래의 당사자가 되는 상거래 |
| **x402** | HTTP 402(Payment Required)를 되살려 접근 시 결제·협상 규격을 반환하는 표준 |
| **a2a-x402** (`x402_a2a`) | 에이전트 간 결제 흐름 표준: `payment-required → submitted → completed` |
| **AP2 / VDC Mandate** | 협상 결과(결제 의도·권한)를 **검증 가능한 자격증명**으로 서명하는 규격 |
| **마이크로 라이선싱** | 건당 0.05 USDC 수준의 초소액 라이선스 즉시 판매 |
| **판매자 AI (Seller Agent)** | 창작자 조건(최소가/목표가/용도)을 대변해 협상하는 Gemini 에이전트 |
| **구매자 AI (Buyer Agent)** | 외부에서 x402로 접근해 자율 협상·결제하는 에이전트 |
| **온체인 앵커링** | 원본 SHA-256 해시를 Solana에 영구 기록해 위변조 불가 증명을 남김 |
| **하이브리드 저장** | 프리뷰(썸네일·워터마크)는 영구, 원본은 전달 후 purge, 해시는 영구 보관 |
| **에스크로 (S3 한정)** | 로열티 분배 시에만 플랫폼 지갑이 수취 후 원작자·2차창작자에게 분할 송금 |
| **창작자 보호 불변식** | 협상가는 창작자가 정한 **최소 허용가 미만으로 절대 확정되지 않음** |

**[시각 구성 제안]** 2열 용어 카드 또는 정의 표. 자주 오해되는 항목(에스크로 S3 한정, 하이브리드 저장)은 강조 색.

## Slide 7 — 핵심 가치 제안 (Value Proposition)

**[페이지 목적]** "누구에게 어떤 가치를 주는가"를 주체별로 정리.

**[핵심 메시지]** "창작자에겐 자동 수익화를, 구매자 AI에겐 즉시 라이선싱을, 생태계엔 신뢰 가능한 결제 레일을 준다."

**[담을 내용]** (3주체 × 가치)

| 주체 | 기존 고통 | VeriProof AI가 주는 가치 |
|------|-----------|--------------------------|
| **창작자** | 무단 사용, 수익화 수단 부재, 협상 부담 | 대화 한 번으로 등록 → AI가 대신 협상 → 온체인 자동 수익·증빙 |
| **구매자 AI / 개발자** | 사람 인증 없이는 결제 불가, 초소액 불가 | 접근 즉시 협상·결제 규격 수신 → 사람 없이 자율 라이선싱 |
| **생태계/플랫폼** | M2M 신뢰·정산 표준 부재 | 위변조 불가 인증 + 표준 프로토콜로 신뢰 가능한 거래 성립 |

- 관통하는 가치 한 줄: **"AI가 창작자에게 정당하게 돈을 지불하는 인터넷."**

**[시각 구성 제안]** 3열(창작자/구매자AI/생태계), 각 열에 아이콘 + Before→After 대비.

## Slide 8 — 4대 차별점 / 핵심 목표 (Key Differentiators)

**[페이지 목적]** 서비스가 반드시 지키는 4개 기둥과 안전장치.

**[핵심 메시지]** "마찰 없는 등록 · AI 자율 협상 · 초소액 온체인 결제 · 위변조 불가 인증 — 그리고 창작자를 지키는 불변식."

**[담을 내용]** (2×2 그리드)
1. **Zero-Friction 등록** — 서식 입력 0회. 대화 한 번으로 이미지 분석·메타데이터·온체인 타임스탬프
2. **Multi-Agent 자율 협상** — 판매자 AI(창작자 조건 방어) ↔ 구매자 AI(예산 최적화) 자율 흥정
3. **HTTP 402 Micro-Licensing** — 무단 접근 차단 + 건당 0.05 USDC 초소액 즉시 결제 (카드 수수료 0원 구조)
4. **위변조 불가 온체인 인증** — 결제 즉시 Solana 장부에 라이선스·해시 영구 기록
- 하단 안전장치: **창작자 보호 불변식** — 협상가는 최소 허용가 미만으로 절대 확정되지 않음
- 지표 배지(참고): "협상 왕복 ≤5초", "서비스 커버리지 ≥85%", "E2E 100% 재현"

**[시각 구성 제안]** 2×2 카드, 각 카드 지표 배지. 하단 불변식은 가로 경고/보증 바.

## Slide 9 — 서비스 전체 그림 (How It Works · Overview)

**[페이지 목적]** 4단계 파이프라인으로 서비스 전 과정을 한 장에.

**[핵심 메시지]** "등록 → 접근 제어 → 자율 협상 → 온체인 정산, 이 4단계가 전부다."

**[담을 내용]** (가로 플로우)
- `① 대화형 등록` — 이미지 업로드 + Gemini 분석 + 최소가/목표가 설정 + 해시 온체인 앵커링
- `② x402 접근 제어` — 외부 AI 접근 시 HTTP 402 + 협상 스펙(JSON) 반환 / 사람은 Solana Pay 분기
- `③ Gemini 자율 협상` — 판매자 AI ↔ 구매자 AI가 `ACCEPT / COUNTER / REJECT`로 흥정
- `④ 온체인 즉시 정산 + 인증서` — USDC 송금 → 서버 tx 검증 → 인증서(Memo) 발급 + 원본 전달
- 하단: "모든 상태 전이는 `AgentEvent`로 기록 → 실시간 타임라인·감사로그"

**[시각 구성 제안]** 4단계가 하나의 파이프로 흐르는 가로 다이어그램. 각 단계 하단에 담당 기술 태그.

## Slide 10 — 핵심 플로우 상세 (Core Flow · Sequence)

**[페이지 목적]** "AI 두 대가 실제로 어떻게 거래를 끝내는가"의 정확한 순서.

**[핵심 메시지]** "402로 규칙을 던지고, AI가 흥정하고, 온체인에서 검증된 돈이 오간다 — 사람 클릭 0회."

**[담을 내용]** (시퀀스: 구매자 AI ↔ VeriProof 서버 ↔ Solana)
1. `GET /ip/{id}` → 서버가 **HTTP 402** + 협상 스펙(JSON) 반환
2. `POST /negotiate` → Gemini 판매자 AI가 `ACCEPT / COUNTER / REJECT` 응답 (최소가 불변식 준수)
3. 합의 → 구매자 → 창작자 **USDC 직접 송금 (P2P)** ※ 로열티(S3)만 에스크로 경유
4. `POST /settle` → 서버가 tx 검증(수취인·mint·금액 일치 + `confirmed`)
5. **인증서 Memo 발행** + 워터마크 제거 원본(만료형 서명 URL) 전달
- 안전장치: `payment_tx_sig` **멱등키**로 이중 정산 방지 / 실패 시 재시도 3회

**[시각 구성 제안]** 세로 시퀀스 다이어그램. 402 JSON 스니펫 축약형을 한쪽에 배치.

## Slide 14 — 결제 프로토콜 스택 (Payment Protocol Stack)

**[페이지 목적]** 자체 규격이 아니라 **공식 표준을 쌓았다**는 점을 명확히.

| 계층 | 표준 | 역할 |
|------|------|------|

- 클라이언트 판별: **AI(x402) → 협상 경로 / 브라우저 → Solana Pay 즉시구매 경로**

**[시각 구성 제안]** 아래→위로 쌓이는 스택. 표준 로고 노출로 신뢰도 강조.

## Slide 15 — 핵심 설계 결정과 원칙 (Design Principles)

**[페이지 목적]** "왜 이렇게 만드는가" — 개발 방향의 근거를 합의.

**[핵심 메시지]** "플랫폼은 자금을 최소로 보유하고, 원본은 지키되 증명은 영구히 남긴다."

**[담을 내용]** (핵심 결정 요약)
- **하이브리드 이미지 저장 (DD-1)** — 프리뷰 영구 / 원본 전달 후 purge / 해시 영구 앵커링 → 저장비 절감 + 원본 전달 요구 동시 충족
- **P2P 직접 결제 + 서버 검증 (DD-3)** — 일반 판매는 구매자→창작자 직접 송금 후 tx 검증. **플랫폼이 자금 미보유(리스크↓)**
- **에스크로는 S3(로열티)에만 (DD-4)** — 분배가 필요한 경우에만 에스크로 경유 실제 분할 송금
- **협상 JSON 구조화 출력 (DD-7)** — Gemini `response_schema` 강제 + 재시도 + **규칙기반 폴백 협상**(불변식 보장)
- **로컬 폴백 = 로직 SSOT (DD-12)** — 비동기 파이프라인과 동기 폴백이 **동일 서비스 메서드** 호출
- **실제 모델 ID 사용 (DD-5)** — `gemini-3.6-flash` / `gemini-3.5-flash-lite` (env 교체 가능)
- **서명키는 Cloud KMS/Secret Manager (DD-11)** — 원시 개인키 미노출, 로컬은 env base58 폴백

**[시각 구성 제안]** 좌측 "결정", 우측 "근거" 2열 정렬. 리스크 완화 관련 항목 강조.
