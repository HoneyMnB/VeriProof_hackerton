## 1. 목표와 핵심 원칙

VeriProof는 양식을 제출하는 사이트가 아니라, 창작자가 자신의 저작물·상품을
등록하고 권리·배포·판매를 준비하도록 돕는 **대화형 창작자 비서 작업공간**이다.

핵심 원칙은 다음과 같다.

1. 대화가 기본 인터페이스이며, 구조화된 입력은 대화를 보조한다.
2. 파일 첨부와 등록 의도는 다르다. **파일을 올렸다는 이유만으로 등록 캔버스를 열지
   않는다.**
3. 등록·공개·결제처럼 되돌리기 어려운 동작은 사용자 확인 전에는 실행하지 않는다.
4. 에이전트의 조언, 사용자 직접 수정, 서버 검증은 서로 분리한다.
5. 공개 자산만 다른 사용자·외부 에이전트가 검색할 수 있다.
6. 검색은 태그·해시 기반의 저비용 후보 선별을 우선하고 Vision 호출은 소수 후보의
   최종 판정에만 제한한다.

## 2. 사용자 역할과 제품 표면

| 주체 | 목표 | 허용 데이터 |
|---|---|---|
| 창작자 | 등록, 권리 설정, 판매·자산 관리 | 본인 비공개·공개 자산, 본인 대화·정산 정보 |
| 창작자 비서 | 안내, 초안 구성, 검색·분석 보조, 실행 준비 | 창작자가 권한을 가진 데이터와 공개 카탈로그 |
| 외부 사용자/에이전트 | 공개 자산 발견, 조건 확인, 라이선스 협상·구매 | 공개·앵커 완료 메타데이터와 보호된 미리보기 |
| 운영자 | 플랜·실체인·인프라 운영 | 운영 권한으로 제한된 관리 데이터 |

공개 Discover는 marketplace 역할을 유지한다. 창작자 워크스페이스는 등록과
자산 관리를 위한 대화 화면이며, 외부 탐색 화면을 사이드바 내부 관리 기능으로
혼합하지 않는다.

## 3. 정보 구조와 화면 책임

### 3.1 좌측 사이드바

참조 프로그램과 같은 낮은 밀도의 고정 탐색 영역만 유지한다.

- 새 대화
- 대화/작업 기록
- 내 라이브러리
- 공개 마켓플레이스
- 좌측 하단 계정 버튼

계정 버튼은 로그인 상태, 표시 이름, 최소 잔액/플랜 상태를 요약하고 클릭 시
설정 모달을 연다. 설정 모달에는 언어, 프로필, 지갑 연결, 구독·결제 설정을 둔다.
수입·지출·행동 지침·판매 내역·지갑 입력 폼을 사이드바에 상시 노출하지 않는다.
이들은 필요한 대화 요청 또는 전용 자산/정산 화면에서 조회한다.

### 3.2 중앙 대화 화면

- 기술용 헤더, 모델 이름, 내부 상태 표시는 제거한다.
- 빈 상태는 “무엇을 등록·관리·탐색하고 싶은가”라는 한 가지 시작점만 제공한다.
- 하단 컴포저는 첨부, 텍스트 입력, 전송만 가진다.
- `+`는 복잡한 양식을 즉시 열지 않고 **첨부**와 **등록 시작**을 선택할 수 있는 작은
  메뉴를 연다.
- 첨부 파일은 대화 흐름 안에서 카드로 보이며 사용자는 분석·검색·등록·취소 중 다음
  의도를 선택한다.

### 3.3 우측 등록 캔버스

등록 의도가 확정될 때만 열리는 보조 작업 영역이다. 자동 팝업이 아니라 다음 중
하나가 트리거다.

1. 사용자가 `+ → 등록 시작`을 선택한다.
2. 첨부 후 “이 저작물을 등록하고 싶다”라고 말하거나 등록 버튼을 누른다.
3. 에이전트가 등록 요청을 명확히 파악하고 사용자에게 “등록 초안을 열까요?”라고
   물은 뒤 사용자가 승인한다.

캔버스는 대화에서 수집된 값과 사용자가 직접 편집한 값을 모두 보여 준다. 필드별
출처(사용자 입력/에이전트 제안)를 표시하고, 사용자의 직접 수정이 항상 우선한다.

## 4. 대화·첨부·등록 캔버스 상태 모델

```text
대화 중
 ├─ 파일 첨부 ──> 첨부됨(등록 아님)
 │                  ├─ 일반 분석/질문
 │                  ├─ 공개 자료 유사 검색
 │                  ├─ 삭제/교체
 │                  └─ 등록 의도 확정 ──> 등록 초안 캔버스 열기
 └─ "등록하고 싶다" ──> 파일 확인 요청 또는 등록 초안 캔버스 열기

등록 초안
 ├─ 정보 수집 중 <──> 사용자 직접 편집
 ├─ 검증 실패 ──> 해당 필드 보완
 ├─ 사용자 최종 확인
 └─ 실행 중 ──> 구독 권한 확인 → 저장/분석 → 앵커 → 인증서 → 완료
```

첨부 상태와 등록 초안 상태는 별도 엔터티로 관리한다. 따라서 하나의 첨부를 단순
질문에 사용한 뒤 나중에 등록할 수 있으며, 등록을 취소해도 대화나 원본 첨부를
자동 삭제하지 않는다.

## 5. 등록 유스케이스와 사용자 확인

### 5.1 정보 수집

에이전트는 첨부와 사용자 발화를 근거로 초안을 제안한다. 수집 대상은 다음과 같다.

- 저작물 유형, 제목, 설명, 제작자
- 공개 여부와 외부 에이전트 검색 허용 여부
- 라이선스 사용 범위, 최소/목표 가격
- 부모 저작물·로열티 관계
- 사용자 입력 태그 및 분석으로 얻은 내부 검색 태그

Gemini의 분석값은 제안일 뿐 사실로 확정하지 않는다. 저작권 소유자, 공개 여부,
판매 조건은 반드시 사용자 선택 또는 명시적 확인이 필요하다.

### 5.2 등록 전 확인 게이트

등록 실행 직전 서버는 다음을 한 화면의 확정 요약으로 제시한다.

- 등록할 파일과 콘텐츠 해시
- 공개/비공개 상태 및 외부 검색 노출 범위
- 라이선스·가격 조건
- 구독 플랜, 이번 등록에 소비되는 이용량
- 로컬 목업/실체인 실행 여부와 생성될 앵커·인증서 범위

사용자는 `등록 확정` 또는 `수정 계속`을 선택한다. 확정 전에는 DB의 실제 자산,
공개 카탈로그, 앵커, 인증서를 생성하지 않는다.

### 5.3 실행과 사후 검증

확정 후의 서버 유스케이스는 구독 권한 재확인, 파일 무결성 검사, 저장, 분석,
미리보기 생성, 앵커, 인증서, 공개 인덱싱을 순서대로 수행한다. 각 단계 결과는
감사 이벤트로 남기며 실패 시 어느 단계도 거짓 성공으로 표시하지 않는다. 완료 후
에이전트는 인증서와 다음 권장 작업을 대화로 설명한다.

## 6. 에이전트 컨텍스트와 행동 경계

에이전트는 일반 챗봇이 아니라 판매자 저작권 비서다. 다음 정보를 읽을 수 있다.

- 로그인 창작자의 대화 이력과 명시적 행동 지침
- 본인 라이브러리, 등록 초안, 인증서, 판매·수입·지출·구독 상태
- 모든 사용자가 공개를 허용한 카탈로그 메타데이터 및 미리보기

다음 행동은 별도 서버 검증과 사용자 확인이 필요하다.

| 행동 | 필수 검증 |
|---|---|
| 등록 초안 변경 | 필드 스키마·소유자·파일 연결 검증 |
| 공개 전환 | 자산 소유권·공개 범위·사용자 확정 |
| 등록 실행 | 구독 잔여량·파일 해시·필수값·확정 토큰 |
| 지출 기록 | 금액·통화·계정 소유권·DB 재조회 |
| 판매/결제 설정 | 권한·조건·결제 모듈 검증 |

모델은 허용된 구조화 명령만 제안한다. 모델 출력이 직접 DB·결제·체인 동작을
실행해서는 안 되며, 모든 실행 결과는 서버가 DB/외부 어댑터에서 재검증한다.

## 7. 공개 자료·유사 이미지 검색 설계

### 7.1 등록 시 1회 수행하는 인덱싱

원본을 저장할 때 검색 전용 파생 데이터도 생성한다.

- 암호학적 콘텐츠 해시: 동일 파일 식별과 무결성 검증
- 지각 해시(perceptual hash): 크기·압축이 달라진 유사 이미지의 빠른 후보 탐색
- 사용자 입력 태그와 Gemini 분석에서 얻은 상세 검색 태그
- 공개 가능한 설명·자산 유형·가격·라이선스·가시성 메타데이터
- 미리보기 썸네일

비공개 자산의 검색 인덱스는 소유자 검색에만 사용한다. 공개 카탈로그 인덱스에는
원본 URL, 비공개 설명, 구매자 데이터, 비밀 키를 넣지 않는다.

### 7.2 질의 시 단계적 검색

1. 에이전트가 사용자 질의를 텍스트·태그·유형·가격·라이선스 조건으로 구조화한다.
2. 먼저 권한 범위 안에서 텍스트/태그와 지각 해시 거리로 후보를 선별한다.
3. 후보 수를 상한으로 제한하고, 필요한 경우에만 썸네일을 한 장의 컨택트 시트로
   합친다.
4. Gemini Vision은 컨택트 시트에 대해 최대 1~2회만 호출하여 질의와의 시각적
   관련성을 판정한다.
5. 에이전트는 근거, 공개 상태, 라이선스·가격, 유사성의 한계를 사용자에게 설명한다.

Vision 호출은 후보가 없거나 텍스트·태그·해시 점수가 이미 충분히 구분되는 경우에는
생략한다. 검색 결과를 “침해” 또는 “표절”로 단정하지 않고 유사 후보로만 제시한다.

## 8. 데이터 모델·모듈 경계

| 새/변경 모듈 | 단일 책임 |
|---|---|
| `apps.ip.models.Attachment` | 대화에 연결된 임시/보관 첨부와 해시 상태 |
| `apps.ip.models.RegistrationDraft` | 등록 초안, 사용자 확정 상태, 첨부 연결 |
| `apps.ip.models.SearchIndex` | 검색 태그·지각 해시·가시성·인덱스 버전 |
| `services.attachment_service` | 안전한 첨부 저장, MIME·크기·해시 검증 |
| `services.registration_draft_service` | 초안 병합, 필수값 검증, 확정 토큰 발급 |
| `services.registration_service` | 확정된 초안만 실제 자산·앵커·인증서로 전환 |
| `services.similarity_search_service` | 후보 선별, 권한 필터, 컨택트 시트 요청 구성 |
| `services.vision_rerank_service` | 제한된 Gemini Vision 재검토와 근거 반환 |
| `apps.ip.views_assistant` | 대화·초안·검색 API의 HTTP 경계 |
| `static/js/workspace.js` | 대화, 첨부 카드, 캔버스 열기/닫기 상태만 담당 |

결제·Solana·저장소·Gemini 어댑터의 현재 모듈 경계는 유지한다. 등록 초안 서비스가
결제나 체인 SDK를 직접 호출하지 않으며, 최종 등록 유스케이스만 해당 어댑터를
조합한다.

## 9. 권한·비용·성능·안전 정책

- 계정별 지갑과 비공개 자산은 세션 소유자 검증 없이 다른 계정에 노출하지 않는다.
- 외부 에이전트는 공개·앵커 완료·공유 승인된 자산만 탐색한다.
- 원본 파일은 공개 검색이나 컨택트 시트에 넣지 않고 보호된 썸네일만 사용한다.
- 대화 첨부는 명시적으로 저장/등록하지 않는 한 공개 자산으로 승격하지 않는다.
- 검색 후보 수, 컨택트 시트 크기, Vision 재검토 횟수는 서버 설정으로 제한한다.
- Vision/검색 실패는 빈 결과를 만들어내지 말고, 사용자가 다시 범위를 조정할 수 있는
  명시적 오류로 반환한다.
- 에이전트의 초안 제안과 사용자 확정 값, 실행 결과, 검증 결과를 감사 로그로 구분해
  저장한다.

## 10. 구현 순서와 검증 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 공통 셸 단순화 | 사이드바에 탐색·계정만 있고 모델 헤더가 없다 |
| 2 | 컴포저·첨부 카드 | 첨부만으로 캔버스가 열리지 않고 대화에 연결된다 |
| 3 | 등록 초안/캔버스 | 등록 의도·명시적 승인에서만 열리고 직접 수정 가능하다 |
| 4 | 확인 게이트 | 확정 토큰 없이는 등록 API가 자산·앵커를 만들지 않는다 |
| 5 | 에이전트 초안 수집 | 대화 응답이 허용 스키마 내에서 초안을 갱신하고 감사된다 |
| 6 | 태그·해시 인덱스 | 공개/비공개 권한 필터를 적용한 후보 검색이 가능하다 |
| 7 | 컨택트 시트 Vision 재검토 | 후보 상한과 최대 2회 호출을 테스트로 보장한다 |
| 8 | 통합 E2E | 첨부→등록 의도→초안→수정→확정→목업 앵커/인증서→공개 탐색을 검증한다 |

각 DB 필드 추가 시 `veriproof/db_reference.md`에 누적 기록하고 Django migration을
추가한다. 단위 테스트는 서비스별 상태 전이를, 통합 테스트는 계정·권한·확정 게이트를,
런타임 E2E는 실제 55000 서버에서 대화와 등록 흐름을 검증한다.
