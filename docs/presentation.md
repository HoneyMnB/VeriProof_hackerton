**[화면 구성]**

  1. 🕷️ **무단 크롤링** — 창작자 IP가 동의·보상 없이 AI 학습에 소비됨

## Slide 5 — 4대 핵심 목표 / 차별점 (Key Differentiators)

**[화면 구성]**
- 2×2 그리드:
  1. **Zero-Friction 등록** — 서식 입력 0회. 대화 한 번으로 이미지 분석·메타데이터·온체인 타임스탬프
  2. **Multi-Agent 자율 협상** — 판매자 AI(창작자 조건 방어) ↔ 구매자 AI(예산 최적화) 자율 흥정
  3. **HTTP 402 Micro-Licensing** — 무단 접근 차단 + 건당 0.05 USDC 초소액 즉시 결제
  4. **위변조 불가 온체인 인증** — 결제 즉시 Solana 장부에 라이선스·해시 영구 기록
- 하단: "창작자 보호 불변식: 협상가는 **최소 허용가 미만으로 절대 확정되지 않음**"

**[발표 스크립트]**
> "네 가지를 목표로 잡았습니다. 마찰 없는 등록, AI 간 자율 협상, 초소액 라이선싱, 그리고 위변조 불가능한 온체인 인증입니다. 특히 중요한 건, 판매자 AI가 아무리 협상해도 창작자가 정한 최소 가격 아래로는 절대 팔지 않는다는 안전장치를 넣었다는 점입니다."

## Slide 6 — 작동 원리: 핵심 플로우 (How It Works)

**[화면 구성]**
- 시퀀스 다이어그램 (구매자 AI ↔ VeriProof 서버 ↔ Solana):
  1. `GET /ip/{id}` → 서버 **HTTP 402** + 협상 스펙(JSON) 반환
  2. `POST /negotiate` → Gemini 판매자 AI가 `ACCEPT / COUNTER / REJECT` 응답
  3. 합의 → 구매자 → 창작자 **USDC 직접 송금** (P2P)
  4. `POST /settle` → 서버가 tx 검증(recipient·mint·amount 일치 + confirmed)
  5. **인증서 Memo 발행** + 워터마크 제거 원본(만료형 서명 URL) 전달
- 사이드 노트: 모든 상태 전이는 `AgentEvent`로 기록 → 실시간 타임라인

**[발표 스크립트]**
> "동작은 이렇습니다. 외부 AI가 이미지에 접근하면 서버가 402와 함께 '이렇게 협상하라'는 JSON을 실어 보냅니다. AI는 그걸 읽고 바로 흥정을 시작하고, 합의되면 솔라나에서 USDC를 직접 송금합니다. 서버는 수취인·토큰·금액이 모두 일치하는지 온체인에서 검증한 뒤, 위변조 불가능한 인증서를 발급하고 원본을 넘겨줍니다. 같은 결제는 두 번 정산되지 않도록 tx 서명으로 멱등 처리했습니다."

**[비주얼/전환]**
- 화살표가 실제 402 JSON 스니펫(축약형)을 스치며 지나가도록 연출.

## Slide 11 — 기술 아키텍처 (Architecture) ★ Google Cloud × Solana

**[화면 구성]**
- 시스템 구조도 (문서 아키텍처 다이어그램 간소화):
  - **Cloud Run**: Django 5 백엔드 (M2M REST + X402 인터셉터 미들웨어)
  - **Service Layer**: Gemini · Solana · X402/AP2 · License · Royalty (외부 I/O 격리, 전부 mockable)
  - **데이터 3계층**: PostgreSQL(SoR) · Firestore(실시간) · BigQuery(감사로그)
  - **비동기 정산 파이프라인**: `pay.sh webhook → Pub/Sub → Eventarc → Workflows`
  - **체인**: Google Cloud Blockchain RPC → Solana Devnet (USDC + Memo), Cloud KMS 서명
- 배지: "주최측 권장 정석 조합 채택"

**[발표 스크립트]**
> "아키텍처는 대회가 권장하는 정석 조합을 그대로 채택했습니다. Cloud Run 위의 Django가 메인 서버이고, 모든 외부 연동은 서비스 레이어로 격리해 테스트가 쉽습니다. 데이터는 PostgreSQL을 기준 원장으로, Firestore를 실시간 현황판으로, BigQuery를 감사 로그로 삼분했습니다. 결제 정산은 Pub/Sub, Eventarc, Workflows로 이어지는 비동기 파이프라인으로 처리하고, 서명 키는 Cloud KMS로 안전하게 관리합니다."

**[비주얼/전환]**
- Google Cloud 제품 로고와 Solana 로고를 실제 데이터 흐름 위에 배치.

## Slide 12 — 결제 프로토콜 스택 (Payment Protocol Stack)

**[화면 구성]**
- 계층형 스택 표:
  | 계층 | 표준 | 역할 |
  |------|------|------|
  | 접근 제어 | **HTTP 402 + x402** | 무단 접근 차단, 협상 스펙 전달 |
  | 에이전트 흐름 | **a2a-x402** (`x402_a2a`) | payment-required → submitted → completed |
  | 결제 의도·권한 | **AP2 Mandate (VDC)** | 협상 결과를 검증가능 자격증명으로 서명 |
  | 결제 실행 | **pay.sh** | 402 감지 + 지갑 서명 + webhook |
  | 사람용 폴백 | **Solana Pay** | Non-agent 클라이언트 고정가 QR |
- 하단: "클라이언트 판별 — AI(x402)는 협상 경로 / 브라우저는 Solana Pay 즉시구매 경로"

**[발표 스크립트]**
> "결제는 자체 규격이 아니라 대회 공식 프로토콜을 쌓아 올렸습니다. x402로 접근을 막고, a2a-x402로 에이전트 결제 흐름을 표준화하고, AP2로 결제 권한을 검증가능한 자격증명으로 서명합니다. AI가 아닌 일반 브라우저가 접근하면 402 대신 Solana Pay QR로 바로 살 수 있게 분기 처리했습니다."

- 스택이 아래에서 위로 쌓이는 애니메이션. 표준 로고 노출로 신뢰도 강조.
